## 1. 模块定位与边界

### 1.1 职责

```
音频输入 ──→ 【语音处理模块】──→ 文本流（partial / final）
                    │
                    └──→ 电平、VAD 事件、错误事件
```

**只做四件事：**

1. 拿到可用的麦克风音频（Web Demo 用笔记本麦克风）
2. 切成 ASR 能吃的帧，边采边传（流式）
3. 判断"人开始说了""人说完了"
4. 输出带置信度的文本，并把异常如实上报

**不做：** 语义理解、对话管理、TTS、口型驱动、噪声场景下的语音分离。

### 1.2 对外接口（唯一契约）

```ts
interface VoiceInput {
  start(opts?: StartOptions): Promise<void>   // 申请权限 + 开始采集
  stop(): Promise<void>                       // 正常停止，flush 尾部音频
  abort(): void                               // 立即中断，丢弃缓冲（打断用）
  pause(): void                               // 暂停采集但不断麦（数字人说话时）
  resume(): void
  on(evt: VoiceEvent, cb: (p: any) => void): void
}

type VoiceEvent =
  | 'ready'          // 麦克风就绪
  | 'speech.start'   // VAD 判定人开始说
  | 'speech.end'     // VAD 判定说完（含 endReason）
  | 'level'          // 实时电平 0~1，驱动 UI 波纹
  | 'partial'        // ASR 中间结果
  | 'final'          // ASR 最终结果（含 confidence）
  | 'error'          // 权限/设备/网络/超时
  | 'silence'        // 长时间无人说话
```

> **关键约束**：上层（对话编排）不允许直接触碰 `MediaStream` / `AudioContext`。只要换收音来源（蓝牙遥控器、手机推流），上层代码一行不改。

## 2. 数据流分层

```
[1] 采集        getUserMedia → MediaStream（48kHz，浏览器原生）
                     ↓
[2] 前处理      降噪 NS → 回声消除 AEC → 自动增益 AGC（浏览器内置）
                     ↓
[3] 重采样      48kHz → 16kHz / 16bit / 单声道
                     ↓
[4] VAD         帧级判断（10ms 帧），带 pre-roll 回溯
                     ↓
[5] 分帧打包     40ms 一包（640 sample）→ Int16Array
                     ↓
[6] 传输        WebSocket 二进制帧 → 服务端
                     ↓
[7] ASR         流式识别 → partial / final
                     ↓
[8] 后处理      医疗热词纠正 → 置信度过滤 → 输出
```

## 3. 采集层（Web 实现细节 + 三个必须知道的坑）

### 3.1 标准调用

```ts
const stream = await navigator.mediaDevices.getUserMedia({
  audio: {
    channelCount: 1,
    echoCancellation: true,     // Demo 靠浏览器内置 AEC，耳机演示可关
    noiseSuppression: true,
    autoGainControl: true,
  },
  video: false,
});
```

### 3.2 三个坑（Demo 现场最容易翻车的点）

| 坑 | 现象 | 解法 |
|---|---|---|
| **安全上下文限制** | 用 `http://192.168.x.x:3000` 打开页面，`getUserMedia` 直接报 undefined | 必须 `http://localhost` 或 HTTPS。局域网 IP 访问不行 |
| **自动播放策略** | `AudioContext` 处于 suspended，没声音 | 首次用户手势（点击"开始"按钮）里调 `ctx.resume()` |
| **默认麦克风选错** | 笔记本有阵列麦+耳麦，默认选到差的 | 启动时 `enumerateDevices()` 列表，允许手动选设备 |

### 3.3 采样率处理（不要偷懒）

不要写成 `new AudioContext({ sampleRate: 16000 })`，Safari 与部分设备不支持任意采样率，会静默回落到 48k，导致 ASR 收到变调音频（识别全错且极难排查）。

**正确做法：** 原生 48k 采集 → 手动线性插值降采样到 16k。

```ts
function downsample(buf: Float32Array, from: number, to = 16000) {
  if (from === to) return buf;
  const ratio = from / to;
  const out = new Float32Array(Math.floor(buf.length / ratio));
  for (let i = 0; i < out.length; i++) {
    const pos = i * ratio, i0 = Math.floor(pos), frac = pos - i0;
    out[i] = buf[i0] * (1 - frac) + (buf[i0 + 1] ?? buf[i0]) * frac;
  }
  return out;
}
```

### 3.4 采集实现

- 用 **AudioWorklet**（`ScriptProcessorNode` 已废弃，会有卡顿和主线程阻塞）。
- Worklet 每 128 sample 回调一次 → 累积到 640 sample（16k 下 40ms）→ `postMessage(Int16Array)`。
- Float32 → Int16 转换时做**软削波**（`Math.tanh` 或限幅到 ±0.98），避免爆音。

## 4. VAD（人声检测）

### 4.1 方案选择

| 方案 | 依赖 | 准确度 | 建议 |
|---|---|---|---|
| 能量 + 过零率 + 自适应底噪 | 无 | 中 | ✅ Demo 用这个，零依赖 |
| Silero VAD（onnxruntime-web） | ~2MB 模型 | 高 | Demo 第二阶段替换 |

### 4.2 能量法核心逻辑

```ts
// 每 10ms 帧计算 RMS
const rms = Math.sqrt(sum(x²) / n);
// 自适应底噪（静默时缓慢跟随）
noiseFloor = 0.995 * noiseFloor + 0.005 * rms;

const isSpeech =
  rms > noiseFloor * 3.0 &&        // 高于底噪 3 倍
  zcr < 0.35 &&                     // 过零率排除摩擦音/键盘
  rms > ABSOLUTE_MIN;               // 绝对下限，防静音房间误触发
```

### 4.3 双阈值 + 预卷（专业细节，别省）

| 机制 | 参数 | 解决什么 |
|---|---|---|
| 起始阈值（高） | 底噪 × 3.0，连续 200ms | 防误触发 |
| 维持阈值（低） | 底噪 × 1.8 | 防句中轻声被判停 |
| **预卷缓冲 pre-roll** | 保留最近 **300ms** 音频 | **防吞首字**（"嗯…我血压高"的"嗯"和"我"常被吞） |
| 判停静音时长 | **1000ms** | 老人句中停顿长，800ms 会截断 |
| 最短有效语音 | 300ms | 过滤咳嗽、碰麦、键盘声 |
| 最长单句 | 20s | 强制收尾，防死循环 |

> **pre-roll 是最容易被忽略、但用户感知最强的一条。** 没有它，老人会说"它老是听不清我第一句"。

## 5. 分帧与传输

| 参数 | 值 | 说明 |
|---|---|---|
| 采样率 | 16000 Hz | ASR 通用 |
| 位深 | 16 bit PCM，小端 | — |
| 声道 | 单声道 | — |
| 帧长 | 40ms = 640 sample = 1280 byte | 延迟与开销平衡 |
| 传输 | WebSocket 二进制 | 不用 base64，省 33% 带宽 |
| 背压 | 缓冲 > 500ms 时丢最旧帧 | 弱网下保实时性，宁可丢音不延迟 |

- 每包带 4 字节头：`seq`（2B）+ `timestampMs`（2B），便于服务端对齐与丢包检测。
- **不要在 VAD 判停前就停止发送**，判停后仍需发送 300ms 尾音，否则句尾吞字。

## 6. ASR 接入与结果后处理

### 6.1 流式时序

```
speech.start ──→ 建立 ASR 会话
   │ 每 40ms 送一帧
   ├─→ partial（每 200–300ms 推一次，用于上屏）
   │
speech.end ──→ 发送尾包 + 结束标记
   └─→ final（200–400ms 内返回）
```

### 6.2 后处理三件事

1. **医疗热词纠正**：维护词表（`血压高→高血压`、`血糖高→高血糖`、`心内→心内科`、`复诊/复查`），对 final 做模糊替换。
2. **置信度过滤**：`confidence < 0.6` 不进入对话逻辑，直接触发"我没听清，您再说一遍"（**不猜测复述**）。
3. **空结果处理**：final 为空 → 等同低置信度，不报错。

### 6.3 partial 的用途（别浪费）

- 实时上屏，让老人看到"它听懂了"——这是**最有效的信任建立手段**。
- 用于**提前预判意图**：partial 出现"挂号"就预热预约技能的号源缓存，省 200–400ms。

## 7. 收音侧状态机

```
        ┌────────┐  start()   ┌─────────┐ VAD起点 ┌─────────┐
        │  INIT  │───────────→│  READY  │────────→│LISTENING│
        └────────┘            └─────────┘         └─────────┘
             │ error               │ pause()          │ VAD终点
             ↓                     ↓                  ↓
        ┌────────┐            ┌─────────┐       ┌──────────┐
        │ ERROR  │            │ PAUSED  │       │ FINALIZING│
        └────────┘            └─────────┘       └──────────┘
                                   ↑ resume()          │ final
                                   └───────────────────┘
                                                        ↓
                                                    ┌────────┐
                                                    │  IDLE  │
                                                    └────────┘
```

| 状态 | 行为 |
|---|---|
| INIT | 申请权限、枚举设备、初始化 AudioContext |
| READY | 麦已开，等待 VAD 触发；持续上报 level |
| LISTENING | 正在送帧；partial 持续上屏 |
| FINALIZING | 已判停，送尾音 + 等 final（最长 2s，超时降级） |
| PAUSED | 数字人说话期间暂停送帧（防自激），麦不关（避免重复申请权限） |
| ERROR | 权限拒/设备丢失/网络断，上报具体 code |

## 8. 打断时的语音侧处理

打断（L1 按键）发生时，语音模块必须做**四件事**，缺一个就会出"打断后它还在自说自话"的 bug：

1. `abort()`：**清空发送队列**，丢弃未发出的 PCM（否则服务端还会收到声音，误判用户又说话了）。
2. ASR 会话立即 `close`，丢弃 in-flight 的 partial 回调。
3. 状态机强制回 `READY`，不经过 `FINALIZING`。
4. **保留 pre-roll 缓冲**：用户按下按键的瞬间可能已经开始说了，pre-roll 能救回前半句。

> 打断后立刻重新进入 LISTENING 时，注意 200ms 内不要触发 VAD（按键音、遥控器"咔"声会被识别成人声）。加**防抖窗口**。

## 9. 降级策略

| 失败点 | 降级动作 | 用户感知 |
|---|---|---|
| 无麦克风 / 权限被拒 | 切键盘输入，界面显示"请用遥控器选择" | 仍可用 |
| 设备被占用（会议软件） | 提示"麦克风被其他程序占用" | 明确可修 |
| 网络断 | 本地缓冲，恢复后补传；> 5s 则丢弃并提示 | "网络不太好" |
| ASR 超时 2s | 用 partial 拼成伪 final；仍空则请重说 | 略慢 |
| ASR 连续 2 次低置信 | 自动切到"按键选择 + 数字键"菜单 | 老人友好 |
| 环境噪声过大（level 长期 > 0.8） | 提示"环境有点吵，靠近一点说" | 可理解 |

## 13. 常见坑速查

| 现象 | 根因 | 修法 |
|---|---|---|
| 识别全错、声音变调 | 采样率没降，48k 当 16k 送 | 手动重采样 |
| 没声音 / 无法采集 | 局域网 IP 非安全上下文 | localhost 或 HTTPS |
| 首字总被吞 | 无 pre-roll | 加 300ms 预卷 |
| 老人说话被截成两段 | 判停太短 | 800→1000ms |
| 打断后它还继续说 | 播放 buffer 没清 | 停 TTS + 清队列 + abort 同时做 |
| 打断后立刻收音失败 | 按键音被当人声 | 加 200ms 防抖 |
| 声音断续 | 主线程阻塞 | 换 AudioWorklet |
| 页面切后台就断 | 浏览器节流 | 演示时禁用切页，或提示 |
| 内存持续涨 | track 没 stop | 每次 stop 释放 MediaStream |
