## 1. 模块职责

**只负责「声音进系统并变成文字」**，不负责语义理解、挂号流程、TTS、嘴型。

对外唯一门面建议命名为 `VoiceInput`：

| 方法 | 含义 |
|---|---|
| `start()` | 开始一轮收音 |
| `stop()` | 正常结束，**等待** final（用户说完） |
| `abort()` | **打断/取消**，丢弃本轮，尽量不产生可用 final |
| `pause()` / `resume()` | 预留（电视切后台等） |

| 事件 | 含义 |
|---|---|
| `ready` | 麦克风与通道就绪 |
| `speech.start` / `speech.end` | VAD 判定人声起止 |
| `level` | 音量，驱动波形 UI |
| `partial` | 中间结果（上屏用） |
| `final` | 最终文本 + 置信度 |
| `aborted` | 本轮已被 abort，业务应忽略后续迟到结果 |
| `error` | 可恢复/不可恢复错误码 |
| `silence` | 静音超时 |

## 2. Demo 三通道（必须可切换）

| 通道 ID | 名称 | 适用 | 说明 |
|---|---|---|---|
| `browser` | 浏览器识别 | 零配置联调 | Web Speech API；Chrome 国内常失败 |
| `cloud` | 云端 ASR | 主推稳定路径 | 录音经服务端代理；OpenAI 兼容或讯飞适配 |
| `mock` | 演示模式 | 无麦/断网 | 预设语句逐字 partial |

切换方式：

- 运行时：设置面板或快捷键（对齐交付包 1/2/3）  
- 配置：`server/config.json` → `asr.provider` / `asr.enabled`  
- 失败降级顺序默认：`browser → cloud → mock`（可由 api-switch 覆盖）

## 3. 数据流（目标规格）

```text
getUserMedia
  → 浏览器 NS/AEC/AGC（能开则开）
  → 重采样到 16kHz 单声道
  → VAD（双阈值 + 预卷）
  → 分帧 / 或整段 MediaRecorder（Demo 云通道可先整段）
  → 传输（HTTPS/localhost 代理）
  → ASR Provider
  → 后处理（热词、置信度）
  → partial / final 事件
```

Demo 优先级：

1. P1：三通道可用 + partial/final 上屏  
2. P2：云通道整段转写（实现快）  
3. P3：流式 WebSocket ASR（降首字延迟）  
4. P4：AudioWorklet + 40ms PCM + 300ms 预卷（对齐交付包目标规格）

## 4. 默认识别参数表（可配置）

以下为 Demo 默认值，写入 `server/config.json` 的 `asr.params` 与前端可读副本（不含密钥）。

| 参数 | 默认值 | 含义 |
|---|---|---|
| `sampleRate` | `16000` | 送 ASR 的采样率 |
| `channels` | `1` | 单声道 |
| `bitDepth` | `16` | PCM 位深（流式时） |
| `frameMs` | `40` | 分帧时长（流式） |
| `vadStartRatio` | `3.0` | 相对底噪，开始说话阈值倍数 |
| `vadStartHoldMs` | `200` | 超过起始阈值需持续毫秒 |
| `vadContinueRatio` | `1.8` | 维持说话阈值倍数 |
| `silenceStopMs` | `1000` | 静音判停 |
| `preRollMs` | `300` | 预卷，防吞老人首字 |
| `minSpeechMs` | `300` | 最短有效语音 |
| `maxSpeechMs` | `20000` | 最长一句话 |
| `lowConfidence` | `0.6` | 低于此值不直接入槽，引导重复 |
| `finalWaitMs` | `2000` | stop 后等待 final 超时 |
| `language` | `zh-CN` | 普通话；预留 `zh-HK` |
| `medicalHotwords` | 数组 | 科室/症状热词表（Demo 内置一小份） |

浏览器通道额外：

| 参数 | 默认值 | 说明 |
|---|---|---|
| `browserSilenceMs` | `1200` | 无新 interim 则结束 |
| `browserLang` | `zh-CN` | SpeechRecognition.lang |

## 5. Provider 接口

```js
/**
 * ASR Provider 统一接口。
 * 不同厂商（OpenAI 兼容、科大讯飞等）都实现同一套方法，方便 api-switch 热切换。
 */
export class AsrProvider {
  /** @returns {Promise<void>} */
  async connect(session) {}

  /** 送入音频块或整段 Blob */
  sendAudio(chunk) {}

  /** 正常结束本轮 */
  finish() {}

  /** 立即取消 */
  abort() {}

  /** 订阅 partial/final/error */
  on(event, handler) {}
}
```

### 5.1 OpenAI 兼容（SenseVoice / 通义兼容网关等）

- Demo 路径：`POST /api/asr`，服务端组 multipart 调 `/audio/transcriptions`  
- 配置：`baseUrl`、`apiKey`、`model`  
- 优点：换厂商常只需改 URL + model  

### 5.2 科大讯飞（适配器位）

- 单独实现 `XfyunAsrProvider`，不强迫塞进 OpenAI 形状  
- 配置项建议：`appId`、`apiKey`、`apiSecret`、`accent`、`vad_eos`  
- 鉴权与 WebSocket 只放在 **server 适配层**，前端仍只打自家 `/api/asr/*`  
- Demo 可先做「录音文件一句话转写」；流式听写作为增强  

### 5.3 MockProvider

- 内置 8–12 句挂号相关话术（如「我最近总是头晕」「挂明天上午」）  
- 定时吐 partial，最后 final，置信度固定 `0.99`  
- `abort()` 时必须清掉定时器，禁止再吐 final

## 7. 打断处理（专章）

电视场景采用 **半双工 + 按键打断（L1）**，不做远场语音抢话。  
本节回答：用户按下打断后，语音模块必须做什么、什么不能做。

### 7.1 谁会触发打断

| 触发源 | 典型按键 | 当时系统状态 | 意图 |
|---|---|---|---|
| 用户打断数字人 | 空格 / 遥控器确认 | `SPEAKING`（文字或 TTS 输出中） | 停播，准备听用户说 |
| 用户取消本轮收音 | 空格再按 / Esc | `LISTENING` | 放弃本轮识别 |
| 强制回待机 | Esc | 任意非危急 | 清会话到 `IDLE` |
| 开新一轮听 | 空格（已 IDLE） | `IDLE` | `start()` 新会话 |

> `stop()` ≠ `abort()`：`stop` 是「我说完了，请给 final」；`abort` 是「不要了，丢弃本轮」。

### 7.2 打断时语音侧必须做的事（硬步骤）

无论 browser / cloud / mock，`abort()` 内部顺序建议固定：

```text
1. 标记本轮 listenId 为 aborted（见 7.4）
2. 停止采集（关闭/停用 MediaRecorder 或 recognition）
3. 调用当前 AsrProvider.abort()
4. 清空待发送音频队列 / 定时器（mock 必清）
5. 重置 VAD 与电平状态
6. 发出 voice.aborted 事件（带 listenId）
7. 保留 pre-roll 缓冲（若已实现），供下一次 start 使用
8. 不向上游业务投递本轮 final（见 7.4）
```

### 7.3 与会话 / 说话模块的完整时序

**场景 A：数字人正在说（text 或 TTS），用户按键打断**

```text
用户按键
  → core: SPEAKING → LISTENING（或先 IDLE 再听，Demo 默认进入听）
  → speak.stopSpeak('user_interrupt')     // 见文档 05：停字幕/TTS
  → avatar 嘴型 sil，动作 listen
  → 若此时误开着收音：voice.abort() 清残局
  → voice.start()                         // 开始听用户
  → 若 LLM 仍在流式：abort fetch，丢弃未播句子
```

**场景 B：正在听用户说话，用户取消**

```text
用户按 Esc 或再次打断键（产品定义为取消）
  → voice.abort()
  → 清 partial 字幕
  → 回到 IDLE（或保持 LISTENING 空波形，Demo 建议 IDLE）
  → 不进入意图/挂号填槽
```

**场景 C：正常说完**

```text
用户松键或静音判停
  → voice.stop()          // 等待 final
  → 收到 final 且 listenId 有效
  → safety → 填槽 / 意图
```

### 7.4 防「幽灵 final」（最容易出的 bug）

云端或浏览器可能在 `abort` 之后仍回调一次识别结果。必须用 **轮次令牌** 丢弃：

```js
// 示意：每次 start 生成新 listenId
let listenId = 0
let abortedIds = new Set()

function start() {
  listenId += 1
  const id = listenId
  // ... 开始识别，回调里带上 id
}

function abort() {
  abortedIds.add(listenId)
  // ... 停设备与 provider
  emit('aborted', { listenId })
}

function onProviderFinal(text, id) {
  if (abortedIds.has(id) || id !== listenId) {
    // 迟到结果：直接丢弃，禁止入槽
    return
  }
  emit('final', { text, listenId: id })
}
```

验收标准：**打断后即使网络晚到，挂号槽位与意图路由都不得变化。**

### 7.5 各通道在 abort 时的注意点

| 通道 | abort 要点 |
|---|---|
| browser | `recognition.abort()`；忽略其后 `onresult` |
| cloud | 停 MediaRecorder；若已 upload 则忽略响应；未 upload 则取消 fetch（`AbortController`） |
| mock | `clearTimeout` / `clearInterval`；标志位禁止再 emit |

### 7.6 打断后的用户体验话术（可选）

| 情况 | 建议 |
|---|---|
| 打断数字人后进入听 | 短提示「我在听」+ 波形 |
| 取消收音 | 「好的，已取消」或不说话直接待机 |
| 打断后用户问「刚才后面说什么」 | 当前 Demo **不接续**（已知短板）；可提示「请再说一次您的问题」 |

### 7.7 与编排层衔接（含打断）

```text
VoiceInput.final（且未 aborted）
  → core.safetyGuard（危急词）
  → 若在挂号槽位中：registration 填槽
  → 否则：intentRouter → ai 或技能

VoiceInput.aborted
  → 不填槽、不调 LLM
  → UI 清 partial
```

低置信度（`< lowConfidence`）：

- 不写入关键槽位（就诊人、确认「对」）  
- 经说话模块提示「我没听清，请再说一次」（前期可用文字模式）
