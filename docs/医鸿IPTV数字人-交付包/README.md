## 一、这个包是什么

本次交付的是**演示验证阶段（Demo）**的完整产物，包含三部分：

| 目录 | 内容 | 用途 |
|---|---|---|
| `01-方案文档` | 3 份方案文档（约 9 万字） | 给院方、广电、评委评审用 |
| `02-交互视觉稿` | 7 屏 1920×1080 高保真视觉稿 | 汇报 PPT、方案答辩、开发对齐 |
| `03-语音对话Demo` | 可本地运行的网页 Demo | 现场演示、技术验证 |

**当前阶段定位**：不做机顶盒适配、不做真 HIS 接口、不做播控报批。目标是先用最低成本证明「老人对着电视上的数字人说话，能得到有用回答」这件事成立。

## 二、快速开始（运行 Demo）

需要 Node.js 18+（无需 npm install，零依赖）。

```bash
cd 03-语音对话Demo
node server.mjs
```

然后浏览器打开：**http://localhost:5173**

> ⚠️ 必须用 localhost 访问，不能双击 HTML 文件。浏览器只在 localhost / HTTPS 下授予麦克风权限。

### 快捷键

| 键 | 功能 |
|---|---|
| `空格` | 开始说话 / 说话时按下 = 打断数字人 |
| `1` | 切换「浏览器识别」通道（零配置，Edge 通常可用） |
| `2` | 切换「云端识别」通道（需在 config.json 配 key，最稳） |
| `3` | 切换「演示模式」（剧本驱动，断网/无麦兜底） |
| `H` | 直接触发危急兜底演示（模拟用户说「胸口疼」） |

### 关于语音识别的现实提醒

Chrome 的中文语音识别走 Google 服务，**国内网络下基本必然报 network 错误**。所以 Demo 做了三通道可切换，且 `1` 失败时会自动降级到 `2` 或 `3`，不会卡死在演示现场。

接真 key 只需改 `03-语音对话Demo/config.json` 两行，改完刷新页面即生效，key 不会落到前端：

```json
{
  "llm":  { "baseUrl": "https://api.deepseek.com/v1", "apiKey": "sk-...", "model": "deepseek-chat" },
  "asr":  { "baseUrl": "https://api.siliconflow.cn/v1", "apiKey": "sk-...", "model": "FunAudioLLM/SenseVoiceSmall" }
}
```

不填也能完整演示，对话走内置 6 组剧本。

## 六、三个值得先知道的技术判断

**1. 不在机顶盒上跑渲染。** 运营商定制老盒子（Android 4.4–9、WebView 老旧、屏蔽 ADB）基本装不了网页应用。正确做法是让盒子当哑终端：只做解码播放 + 回传遥控器键值，渲染在云端或在笔记本。这恰好就是真 IPTV 的生产架构。

**2. 全双工打断在电视上做不了。** 电视外放 65–75dB，3 米外的麦克风收到的自己声音比用户说话还响，会回声自激。机顶盒无双麦阵列、做不了远场 AEC。所以打断放在**遥控器按键**上——L1 级打断，100% 可靠。

**3. 数字人在挂号场景的价值是「导诊」，不是「挂号」。** 公众号早就能挂号，电视端加一个入口没有增量。真正的增量是：老人说不清看哪个科，数字人帮他定科室、压步骤、念确认。所以自建重心在导诊知识库与家庭账户，对接重心在号源与身份。
