## 2. 分层架构

```
接入层   HTTP / WebSocket / 未来机顶盒遥控器键值
  ↓
会话层   状态机 + 单轮上下文（IDLE→LISTENING→THINKING→SPEAKING）
  ↓
编排层   ASR → 安全拦截 → 意图路由 → 槽位追问 → 应答生成 → TTS → 口型
  ↓
能力层   Provider（ASR/LLM/TTS 可换）+ Tool（HIS/预约/报告，先 Mock）
  ↓
数据层   知识切片 + 事件录制（JSONL，可 1:1 回放）
```

**硬约束：编排层不直接调用任何云厂商 SDK，只依赖接口。** 换模型、换厂商、换私有化部署只改 `config/default.yaml`。

### 2.1 四个核心抽象

```ts
// 1) 三大 Provider —— 换厂商只换实现
interface ASRProvider {
  transcribe(stream: AsyncIterable<AudioFrame>):
    AsyncIterable<{ text: string; isFinal: boolean; confidence: number; ts: number }>
}

interface LLMProvider {
  chat(messages: Msg[], opts: { tools?: ToolSchema[] }):
    AsyncIterable<{ delta?: string; toolCall?: ToolCall }>
}

interface TTSProvider {
  synth(text: string, voice: string):
    AsyncIterable<{ audio: Buffer; visemes: { t: number; v: Viseme }[] }>
}

// 2) Tool —— 后续接 HIS 全靠它，第一天就留位
interface Tool {
  name: string                              // querySchedule / queryReport / createAppointment
  schema: JSONSchema                        // 给 LLM 做 function calling
  handler(args: unknown): Promise<ToolResult>  // 现在返回 Mock 数据
}

// 3) 收音来源抽象 —— 机顶盒没麦克风，这是必做的一层
interface AudioSource {
  kind: 'mic_local' | 'bt_remote' | 'phone_bridge'
  start(): void
  stop(): void
  onFrame(cb: (pcm: Int16Array) => void): void
}
```

## 3. 对话模式：半双工为主，架构预留全双工

### 3.1 关键判断

电视外放时数字人音量 65–75dB，3 米外的麦克风收到的**自身回声比用户说话还响**。麦常开会导致回声自激：数字人听到自己说话 → 回应自己 → 听众认为系统"坏了"。而 IPTV 机顶盒没有双麦阵列，做不了远场 AEC。

**结论：打断功能必须做，但打断通道放在按键上，不依赖常开麦。**

### 3.2 模式对比

| 模式 | 做法 | 客厅可行性 | 结论 |
|---|---|---|---|
| 全双工 | 麦常开，随时说随时打断 | ❌ 回声自激、误触发 | 架构预留，不上线 |
| **半双工 + 按键打断** | 按键/唤醒进入听，说完自动判停 | ✅ 稳定 | **主线** |
| 按键说话（PTT） | 按住说，松开停 | ✅ 最稳 | 老人不习惯长按，作兜底 |

Demo 阶段：**VAD 自动判停（主）+ 按键打断（打断通道）**。

## 4. 打断策略（四级）

| 级别 | 触发方式 | 实现 | 采纳 |
|---|---|---|---|
| L0 不可打断 | 无 | 播报中屏蔽输入 | 仅用于急救指引、免责声明 |
| **L1 按键打断** | 任意遥控器键 / 空格键 | 停 TTS + 停字幕 + 进 LISTENING | ✅ **Demo 采用** |
| L2 语音打断 | 麦常开 + AEC，人声能量 > 回声估计 | 需双麦远场 | 架构预留 |
| L3 语义打断 | 数字人说完一句才响应 | 排队下一轮 | 兜底策略 |

### 4.1 L1 打断的五个技术要点

1. **TTS 流可取消**：用 `AbortController`，不是"等这段播完"。
2. **服务端 LLM 流同步中断**：否则打断后模型继续生成，白烧 token 与并发。
3. **播放器立即静音 + 清空 buffer**：只调音量不够，已缓存音频稍后会继续吐出来。
4. **上下文标记"未说完"**：用户问"刚才后面说什么"能接得上。这是体验分水岭。
5. **打断响应 < 100ms**：从按键到静音的感知延迟上限。

### 4.2 打断后的界面行为

- 字幕**不回滚**，保留在屏幕并淡化为灰色历史，新回应在下方续写。
- 数字人动作切到"倾听"姿态，不再做原动作的收尾动画。
- 若打断发生在工具调用中，工具结果丢弃，不补播。

## 5. 收音方案

### 5.1 来源抽象（IPTV 项目最容易做错的地方）

机顶盒本身无麦克风，收音来源必须抽象：

| 来源 | 场景 | Demo 是否实现 |
|---|---|---|
| `mic_local` | 笔记本麦克风 / 电视 USB 麦 | ✅ 实现 |
| `bt_remote` | 蓝牙语音遥控器（新盒子支持） | 留接口 |
| `phone_bridge` | 手机扫码后手机当麦，音频推服务端 | 只做浮层，不真做 |

### 5.2 技术链

```
麦克风 → 降噪 NS → 回声消除 AEC → 自动增益 AGC → VAD → 分帧(40ms) → WebSocket → 流式 ASR
```

- Demo 阶段 AEC 用浏览器内置（`echoCancellation: true`）足够，因为笔记本是近场。
- 采集用 **AudioWorklet**（`ScriptProcessor` 已废弃，不要用）。
- 上远场时替换为 WebRTC AEC3，接口不变。

### 5.3 收音参数定稿

| 参数 | 值 | 说明 |
|---|---|---|
| 采样率 | 16kHz / 16bit / 单声道 | ASR 通用规格 |
| 分帧 | 40ms | 兼顾延迟与开销 |
| VAD 起始 | 连续 200ms 人声 | 老人起音弱，别设太严 |
| VAD 判停 | **静音 1000ms** | 老人说话有停顿，800ms 会截断 |
| 最短有效语音 | 300ms | 过滤咳嗽、键盘声 |
| 最长单句 | 20s | 超时强制收尾 |
| 静音超时 | 15s 追问 / 30s 回待机 / 180s 屏保 | 三级 |

## 6. 状态机

```
              ┌──────────────────────────────┐
              ↓                              │
   ┌──────┐ 按键/唤醒  ┌──────────┐ asr.final ┌──────────┐
   │ IDLE │──────────→│LISTENING │──────────→│ THINKING │
   └──────┘           └──────────┘           └──────────┘
      ↑                    ↑                      │ 首 token
      │ 30s 超时           │                      ↓
      │                    │ 打断(L1)        ┌──────────┐
      │                    └─────────────────│ SPEAKING │
      │                                      └──────────┘
      │                                           │ 播完
      └───────────────────────────────────────────┘
```

### 6.1 转移表

| 当前 | 事件 | 下一状态 | 动作 |
|---|---|---|---|
| IDLE | 按键 / 唤醒 | LISTENING | 开始采集，播"滴"提示音，数字人转倾听姿态 |
| LISTENING | asr.partial | LISTENING | 逐字上屏（让老人看见"听懂了"） |
| LISTENING | asr.final | THINKING | 关麦，进编排 |
| LISTENING | 静音 15s | LISTENING | "还需要我帮您做点什么吗？" |
| LISTENING | 静音 30s | IDLE | 回待机 |
| THINKING | 首 token | SPEAKING | 首句完整即送 TTS，不等全文 |
| THINKING | LLM 超时 5s | THINKING | 先播"我查一下，稍等"垫音，继续等 |
| SPEAKING | 播完 | IDLE | turn.end，记 JSONL |
| SPEAKING | 任意键（L1） | LISTENING | 停 TTS、清 buffer、中断 LLM 流、上下文标"未说完" |
| 任意 | 命中危急词 | EMERGENCY | 立即打断一切，播 120 指引，红条大字，L0 不可打断 |
| 任意 | 网络断 | DEGRADED | 切预录回放包 |

### 6.2 特殊分支

| 事件 | 处理 |
|---|---|
| ASR 置信度 < 0.6 | "我没听清，您再说一遍"，**不猜测复述** |
| ASR 返回空 | 不报错，等同低置信度处理 |
| TTS 失败 | 降级纯字幕 + 提示音 |
| 工具调用失败 | "这个暂时查不到，我帮您转人工/给菜单" |

## 7. 单轮处理流程与延迟预算

```
用户按键 ──→ [LISTENING] 采集 + 实时 VAD
              │ asr.partial 逐字上屏
              │ 静音 1s → asr.final
              ↓
         [安全规则] ← 5ms，命中即短路到 EMERGENCY（在 LLM 之前）
              ↓
         [意图路由] ← 规则优先，命中"挂号/报告/复诊"走槽位脚本
              ↓
         [THINKING] LLM 流式，首句完整立即送 TTS
              ↓
         [SPEAKING] tts.chunk 播放 + avatar.viseme 驱动口型
              │ 任意键 → 打断 → 回 LISTENING
              ↓
            turn.end → 记 JSONL
```

| 步骤 | 延迟预算 | 优化点 |
|---|---|---|
| VAD 判停 → speech.end | 1000ms（固定，不可压） | 老人停顿长，宁可慢 |
| ASR final | 200–400ms | 医疗热词表必须加载 |
| 安全规则前置 | < 5ms | 纯规则引擎，不调模型 |
| 意图路由 | 5–50ms | 规则 + 关键词，不上小模型 |
| LLM 首 token | 300–800ms | 流式；首句完整即送 TTS |
| TTS 首包 | 200–400ms | 流式合成，不等整段 |
| 口型驱动 | 0 | 靠 TTS 返回音素时间戳，无需推理 |
| **首字响应合计** | **1.7–2.7s** | 超标优化：ASR partial 阶段预判意图预热 LLM |

> VAD 判停固定 1s 是刻意的：老人说话中段停顿常见，压到 800ms 会截断成"半句话"，后续全错。宁可慢 0.2s。

## 8. 意图路由与技能

### 8.1 路由策略（规则优先，LLM 兜底）

| 优先级 | 命中条件 | 走向 |
|---|---|---|
| 1 | 危急词库命中 | EMERGENCY，短路 |
| 2 | 高频指令词（挂号/报告/复诊/缴费） | 固定 Skill 脚本（槽位驱动，不调 LLM 生成话术） |
| 3 | 知识切片关键词命中（高血压/糖尿病/用药…） | RAG + LLM 生成 |
| 4 | 未命中 | 通用 LLM + 兜底话术 |

> 固定技能走脚本而非 LLM，是为了**保证话术稳定、可审核、不幻觉**。挂号流程的话术必须医务科签字，不能让模型自由发挥。

### 8.2 v0.1 技能清单

| Skill | 槽位 | Mock 数据 |
|---|---|---|
| `appointment` 预约挂号 | 科室 → 日期 → 时段 | 假号源 3 科室 × 3 天 |
| `report` 报告查询 | 就诊卡号 → 报告类型 | 假报告 2 份 |
| `followup` 复诊提醒 | 无（读会话画像） | 假提醒 2 条 |
| `faq` 通用问答 | 无 | 15 条知识切片 |

**槽位追问规则：每轮只问一个槽位，最多问 2 轮，第 3 轮给菜单/转人工。**

## 9. 安全边界

### 9.1 危急词前置拦截（必须硬编码，不交给模型判断）

| 类别 | 触发词示例 | 响应 |
|---|---|---|
| 心血管 | 胸口疼、胸闷、心慌、喘不上气 | 红色警示条 + "请马上拨打 120" + 大字急救指引 |
| 神经 | 说不出话、半边身子麻、嘴歪、抽搐 | 同上 |
| 出血 | 吐血、呕血、便血、大出血 | 同上 |
| 意识 | 昏迷、叫不醒、意识不清 | 同上 |
| 自伤 | 不想活、自杀 | 心理危机话术 + 热线 + 转人工 |

### 9.2 禁答域（Prompt 层 + 规则层双保险）

- 不做诊断、不给用药剂量、不判断检查结果良恶性
- 不推荐具体药品商品名
- 不承诺疗效（广告法）
- 不评价其他医院/医生
- 涉及以上，统一话术："这个需要医生面诊判断，我帮您挂号"

### 9.3 合规标识

- 数字人形象旁常驻「AI 生成」角标
- 知识切片标注「内容经 XX 科审核」
- 首屏或片尾免责声明（文案待院方提供）

## 10. 老人场景硬规则（决定产品成败，不是优化项）

1. **每轮只问一个问题**。绝不说"您挂哪个科、哪天、上午下午"。
2. **必须复述确认**："您是想挂心内科，明天上午，对吗？"
3. **语速 0.85x，单句 ≤ 20 字**，句间停 0.5s。
4. **ASR 低置信度不复述猜测**，直接请用户重说。猜错比听不清更伤人。
5. **槽位追问最多 2 次**，第 3 次给菜单/转人工。
6. **数字口语化**：不说"3 月 5 日 14:30"，说"三月五号下午两点半"。
7. **字幕常驻**，48–64px（以电视实测为准），高对比、不透明底，关键词可加粗。
8. **方言**：深圳场景至少备粤语 ASR 通道，客家话视院方需求。

## 11. 异常兜底清单

| 情况 | 处理 |
|---|---|
| 用户沉默 15s | 主动问"还需要我帮您做点什么吗？" |
| 多人抢话 | 取能量最强声源，提示"请一个人说" |
| 电视本身在放声音 | 提示"先把电视声音调小"或自动降音 |
| ASR 返回空 | 不报错，说"没听清"，回 LISTENING |
| 用户重复同一句 | 第 2 次换说法解释，第 3 次转菜单 |
| 用户说"不聊了" | 礼貌收尾回 IDLE，不纠缠 |
| 网络抖动 | 首字超 2.5s 先播"稍等"垫音 |
| 现场断网 | 切 JSONL 回放包 / 预录视频 |

## 12. 事件协议（前后端唯一通信语言）

| 方向 | 事件 | 说明 |
|---|---|---|
| C→S | `session.start` | 建立会话，带设备/形象参数 |
| C→S | `speech.start` / `speech.end` | 录音边界 |
| C→S | `speech.chunk` | 二进制 PCM 帧（40ms） |
| C→S | `text.input` | **调试通道**，打字模拟说话（M1 全靠它） |
| C→S | `ui.key` | 遥控器键值（真机测试用） |
| C→S | `interrupt` | 打断 |
| S→C | `session.ready` | 会话就绪 |
| S→C | `asr.partial` / `asr.final` | 中间结果 / 最终句（含置信度） |
| S→C | `safety.alert` | 危急拦截，独立事件，前端出红条 |
| S→C | `llm.delta` | 逐字上屏 |
| S→C | `tool.call` / `tool.result` | 展示"正在查号源" |
| S→C | `tts.chunk` | 音频分片 |
| S→C | `avatar.viseme` | 口型时间戳序列 |
| S→C | `ui.state` | 状态同步（IDLE/LISTENING/…） |
| S→C | `turn.end` | 单轮结束，触发落盘 |
| S→C | `error` | 错误 |

**所有事件写入 JSONL**，一条命令 1:1 回放。既方便调试，也是演示现场断网的救场手段。

## 15. 附录 A · 旧机顶盒探测清单

拿到盒子后半小时内完成，结果决定 Track B 分支。

| # | 探测项 | 方法 | 用途 |
|---|---|---|---|
| 1 | 型号与系统版本 | 设置→关于；或 `adb shell getprop ro.build.version.release` / `ro.product.model` | 判断有无必要继续 |
| 2 | 能否 ADB | 同网段 `adb connect 盒子IP:5555`；或 USB 双公头 | 决定壳 APK 怎么装 |
| 3 | 能否 U 盘装 APK | 插 U 盘，看文件管理器是否可见、是否允许未知来源 | 侧载第二通道 |
| 4 | 解码能力 | 播 1080p50 / H.264 / 8Mbps 的 HLS 测试流 | 决定推流码率与分辨率上限 |
| 5 | 遥控器键值 | `adb shell getevent -l`，逐个按键记 KEY_XXX | 壳 APK 映射表 |
| 6 | 电视实际观感 | 3 米外看：字幕多大看得清、数字人占屏多少合适 | **最值钱**，定 UI 尺寸规范 |

**分支判断：**

- 能装 APK → 做壳 APK（全屏播放流 + `onKeyDown` 回传键值），等同生产架构。
- 完全锁死 → 只做「观感校准」，Track A 照常演示，真机集成留给 P0。
